# Дорожка — журнал одного тренера по плаванию

Сервис для **одного** тренера. Клиенты сервисом не пользуются и сообщений не получают.
Интерфейс, тексты, коммиты и ответы пользователю пишутся на русском.

## Устройство

- `dorozhka.html` — всё приложение в одном файле: разметка, CSS и vanilla JS, без сборщика и фреймворков. Режим зависит от того, где открыт файл:
  - **облако** (`window.DOROZHKA_CLOUD`, сайт на Vercel): вход через Telegram-бота, данные в Supabase;
  - **локальный сервер** (`server/server.mjs`, порт 4318): SQLite в `data/`;
  - **демо** (файл открыт напрямую): `localStorage` и `seed()`.
- Всё состояние — один JSON-документ `S` (`clients`, `groups`, `sessions`, `payments`, `prices`, `settings`, `vacations`). Изменения сохраняются через `persist()`, после чего вызывается `render()` или открывается нужный лист. В облаке документ лежит в таблице `app_state`, а сохранение проверяет версию через RPC `save_state`.
- `shared/schedule.mjs` — логика напоминаний (`dueMessages`, `wallNow`, `durOf`). Её используют и локальный сервер, и edge-функция. `cloud/build.mjs` копирует этот файл в `cloud/supabase/functions/_shared/`.
- `cloud/supabase/functions/telegram/index.ts` — edge-функция на Deno. Маршруты:
  - `/tick` — cron;
  - `/hook/<secret>` — webhook бота;
  - `/login/start`, `/login/poll` — вход через бота;
  - `/status`, `/connect`, `/test`, `/disconnect`.
- `cloud/supabase/migrations/` — SQL. По умолчанию API-ролям не выданы никакие права, поэтому каждую новую таблицу открывают явными `grant` и защищают RLS.

## Правила учёта (не ломать)

- Длительность: грудничковое — 30 мин, остальные типы — 45 мин (`DUR`).
- Абонемент списывается, если клиент был или не предупредил (`charged()`). Если клиент предупредил, занятие не списывается.
- Пробное занятие никогда не списывается.
- Занятия во время паузы клиента не списываются. Отметки, поставленные до паузы, остаются.
- Сплит — это всегда пара: один клиент на сплит или двое (`SPLIT_N`, `heads()`, `attWeight()`).
- Группа и мини-группа: от 1 человека, без верхнего предела (`GROUP_MIN`).
- Тренировки по абонементу (`planDates`) создаются ровно в указанном количестве и никогда не продлеваются сами. Дни отпуска тренера пропускаются.
- У каждого дня плана своё время (`c.plan.slots`). Свободное время (`suggestSets`) ищется в рабочих часах `S.settings.hours` с перерывом `breakMin` и шагом `stepMin`. Занятыми считаются все неотменённые занятия тренера.
- Напоминания уходят только тренеру в Telegram.

## Команды

```bash
node cloud/build.mjs                                                    # собрать cloud/web
npx vercel deploy --prod --yes --cwd cloud/web                          # выложить сайт
npx supabase functions deploy telegram --no-verify-jwt --workdir cloud  # выложить функцию бота
npx supabase db query --linked --workdir cloud -f supabase/migrations/<file>.sql  # применить миграцию
```

- `supabase db push` здесь не работает. После `db query` добавьте версию миграции в `supabase_migrations.schema_migrations`.
- Node лежит в `~/.local/node/bin`, gh — в `~/.local/gh/bin`.
- Предпросмотр: конфиг `dorozhka` в `.claude/launch.json` (порт 4317, демо-режим).

## Проверка изменений

- Синтаксис скрипта: вытащить содержимое `<script>` и прогнать через `new Function(...)` в node.
- Поведение: открыть предпросмотр, вызвать функции приложения из консоли (`clientSheet`, `newSessionSheet`, `requestSubmit()`) и проверить `S`. Смотреть и ширину телефона (375 px), и тёмную тему.
- После изменений, которые видит пользователь, обновить README («Возможности», «Правила учёта», «Дорожная карта»).

## Безопасность

- Никогда не выводить и не коммитить токен бота, service role key, секреты cron и webhook. Ключи и пароли пользователь вставляет в файлы сам, в чате их не просить.
- В git можно хранить только anon-ключ из `cloud/config.json` (он публичный, данные закрывает RLS).
- Не запускать локальный сервер с настоящим ботом, пока в облаке включён webhook.
- Внешние скрипты подключать с точной версией и SRI.
